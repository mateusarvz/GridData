# Product

## Register

product

## Users

Equipes mistas de profissionais técnicos e não-técnicos em empresas que precisam organizar, estruturar e gerenciar dados empresariais. Analistas de dados, gestores de negócio e desenvolvedores que precisam modelar bancos de dados relacionais e gerenciar datasets sem dominar SQL. Usam o sistema em ambiente de escritório, durante o horário de trabalho, em telas de desktop, com foco em produtividade e clareza.

## Product Purpose

Dama Box é uma plataforma de Data Management + Semantic Layer que permite aos usuários organizar dados empresariais visualmente — criando tabelas dinâmicas, definindo relacionamentos entre datasets, importando arquivos e construindo uma camada semântica sobre seus dados. O objetivo é democratizar a modelagem de dados, tornando-a acessível a quem não tem conhecimento técnico em SQL, enquanto mantém o poder e a flexibilidade que profissionais técnicos precisam. Sucesso é quando um gestor de negócios consegue modelar e consultar seus dados tão naturalmente quanto organiza pastas no computador.

## Brand Personality

Amigável, Intuitivo, Elegante. O Dama Box fala com confiança serena — nunca intimidador, nunca simplista demais. O tom é de um colega experiente que explica com clareza, não de uma ferramenta corporativa que exige treinamento. A elegância vem da simplicidade estrutural, não de decoração.

## Anti-references

- **Interfaces corporativas pesadas e datadas** (Oracle, SAP, ferramentas enterprise legacy): telas sobrecarregadas de informação, menus infinitos, estética dos anos 2000, curva de aprendizado íngreme.
- **Ferramentas super técnicas com UI de terminal/hacker**: dark mode agressivo com texto verde/neon, interfaces que parecem consoles de comando, que excluem usuários não-técnicos.
- **Referência positiva:** Airtable — tabelas dinâmicas com visual limpo, interface que parece uma planilha moderna mas com poderes de banco de dados.

## Design Principles

1. **Organizar é navegar** — A estrutura dos dados deve ser visível e manipulável diretamente. Pastas, tabelas e relações são objetos que o usuário toca e arrasta, não registros que ele consulta em formulários.
2. **Progressividade honesta** — Cada tela mostra exatamente o que o usuário pode fazer agora, sem esconder funcionalidades atrás de menus profundos nem prometer features que não existem.
3. **Familiaridade com propósito** — Usar padrões que o usuário já conhece (pastas, cards, drag & drop, breadcrumbs) ao invés de inventar affordances novas. A inovação está na combinação, não nos controles.
4. **Silêncio visual** — Cada elemento na tela justifica sua presença. Se não contribui para a tarefa atual, não aparece. Espaço em branco é uma decisão, não um descuido.
5. **Confiança pelo feedback** — Toda ação do usuário recebe resposta visual imediata. Arrastar mostra onde vai cair. Criar mostra o que foi criado. Deletar pede confirmação. Nunca silêncio.

## Accessibility & Inclusion

- WCAG AA compliance (contraste mínimo 4.5:1 para texto, 3:1 para elementos gráficos)
- Suporte a navegação por teclado em todos os componentes interativos
- Suporte a `prefers-reduced-motion` para animações
- Labels e ARIA roles em todos os elementos interativos
- Foco visível em todos os componentes
